# Upstream exploit verification

Dynamic-first verification of the 56 CVEs/advisories and 70 mining candidates.
Only a case that reproduces the vulnerable path against the pinned real upstream
version becomes `verified`; static-only and unsupported cases never enter the
exploitable list.

## Layout

```
cases/<component>/<case-id>/
  manifest.json   pinned version/commit, root cause file:line, preconditions,
                  steps, expected evidence, cleanup, status/method/python
  poc.py          repeatable PoC or static/advisory check
  evidence/       request/response, marker, source hashes, logs
  result.json     generated by the harness
upstream/         vendored third-party source snapshots (read-only; hashes in
                  each manifest and upstream/sources.json)
pocs/             PoC templates copied into cases by the builder
```

`python` in a manifest is a logical key (`reproenv`, `litellm`, `mlflow3`,
`mlflow2`, `torch`, `lfa`, `ray280`), resolved by `harness.py`; this keeps host
drive paths out of the committed tree.  `ray280` is a dedicated cp311
interpreter under `.envs/` (gitignored) because Ray 2.8.0 has no cp312 wheel;
its setup and the two host shims (absent `nvidia-smi`/`wmic`, Ray's Windows
`preexec_fn` bug) are documented in the `CVE-2023-48022` manifest.

Service-level cases use `lab/upstream_verify/servicelib.py` to start/stop the
real daemon (`RayHead`) and to talk HTTP with an unprivileged client.
Static-only cases must declare `static_blocker = {category, reason}`; the
taxonomy is enforced by `tools/verify-exploits.py` and rendered in
`docs/EXPLOIT-VERIFICATION.md`.

## Commands

```powershell
python -m lab.upstream_verify --list
python -m lab.upstream_verify --all
python -m lab.upstream_verify --id CVE-2025-32444
python tools/verify-exploits.py
python -m unittest tests.test_exploit_verification
```

`inkblade/core/exploit-registry.json` is the machine-readable source of truth;
`docs/EXPLOIT-VERIFICATION.md` is the human report. CVE catalog, version matrix
and CVE module findings carry the same verdict.

## Status meanings

- `verified`: dynamic reproduction against a pinned upstream version, exit 0,
  proof marker and hashed evidence.
- `static-only`: root cause/sink present but not dynamically reproduced; must
  not be reported as weaponized/exploitable.
- `unsupported`: hardware/Linux-runtime/vendor-firmware path cannot run on this
  host; explicitly excluded from counts of verified capabilities.
