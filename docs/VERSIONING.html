Versioning, compatibility and deprecation

Semantic Versioning 2.0.0. Tags are v-prefixed; pre-releases use -rc.N / -beta.N.

ComponentBumped when
MAJORa documented contract breaks: CLI flags/exit codes, report schema, manifest contract, sdk.api, HTTP API, evidence layout
MINORbackward-compatible additions: modules, commands, optional manifest fields, export formats
PATCHbackward-compatible fixes only: security, false positives, docs, performance

While MAJOR == 0: a MINOR bump may break something, but only through the deprecation cycle below and a "Breaking" entry in CHANGELOG.md. At 1.0.0 the windows become binding.

Deprecation

PhaseRequirement
AnnounceCHANGELOG.md under "Deprecated", and in --help where the flag lives
Keepone MINOR cycle, minimum 30 days
Removenext MINOR (0.x) or next MAJOR (1.x+), with a "Removed" entry naming the replacement
Securitya fix may shorten the cycle; it does not skip the changelog entry
