English

The scan path has no model in it

Recon, module execution, chain planning, evidence, exports and the body of every report run on the Python standard library. Nothing in that path loads weights, calls an inference server or needs a key. A laptop with the network unplugged produces the same plan, the same evidence tree and the same report as a host with an endpoint configured.

A model, when you attach one, reorders work the rule engine already proposed. It cannot invent a module, widen a scope, lower a technical level or approve an action.

Where a model can be called

PathWhat the model doesWith no endpoint
explore proposeRanks the candidate list produced by the deterministic planner, returns at most five module keysRules order the list: read-only first, asset-targeted first
explore autonomy --autonomy L3Same ranking inside the pre-authorized loop--llm refuses at preflight; without --llm the loop runs on rules
report-ctemWrites one optional narrative paragraph from a facts dictionaryA fixed template paragraph

Everything else stays local: collect, discover, module runs, chains, backup, rollback, the three evidence layers, report sections, SARIF/OCSF/VEX export and rule generation.

Two ways to attach an endpoint

Pool, llm_pool.json. Several endpoints, weights, per-endpoint quotas, cooldown and failover. This is what explore prefers once it is enabled. Two ways to enable it: "enabled": true in the file, or the environment variable INKBLADE_LLM_POOL=1.

One endpoint by environment. INKBLADE_LLM_BASE_URL, INKBLADE_LLM_API_KEY and INKBLADE_LLM_MODEL. The explorer and the L3 preflight read these. There are no weights, quotas or health records on this path, and it is never enabled by accident: no base URL, no calls. When both exist, the pool is tried first and the environment endpoint is the fallback.

export INKBLADE_LLM_API_KEY_LOCAL='<token>'
export SCHEME=https                # plaintext scheme only on loopback

# add one endpoint, then switch the pool on (lead or admin)
inkblade --home ./lab llm-pool add --workspace local-lab --role lead \
  --base-url "$SCHEME://127.0.0.1:8000/v1" \
  --model local-instruct \
  --api-key-env INKBLADE_LLM_API_KEY_LOCAL \
  --weight 1 --quota-requests 200 --quota-tokens 200000

inkblade --home ./lab llm-pool enable --workspace local-lab --role lead
inkblade --home ./lab llm-pool health --workspace local-lab --role lead

$SCHEME is https for a TLS gateway, or http only on loopback. add writes the entry but does not enable the pool; enable does. health sends GET /models to every enabled endpoint and needs the pool to be on.

llm_pool.json

The CLI writes it to <home>/evidence/<workspace>/llm_pool.json. Hand edits are fine; the file is read on every call. A minimal file:

{
  "enabled": true,
  "endpoints": [
    {
      "id": "ep-01",
      "base_url": "<scheme>://127.0.0.1:8000/v1",
      "model": "local-instruct",
      "api_key_env": "INKBLADE_LLM_API_KEY_LOCAL",
      "weight": 1,
      "quota_requests": 200,
      "quota_tokens": 200000
    }
  ]
}
FieldRequiredMeaning
enabledyesMaster switch. Missing or false means every complete call raises PoolDisabled.
endpoints[].idnoStable name; generated as ep-01, ep-02 when omitted.
base_urlyesOpenAI-compatible root. Host part is 127.0.0.1:8000/v1; the loader rejects a value without a transport scheme, so write <scheme> as your gateway's scheme.
modelyesModel name sent in the request body.
api_keyone ofLiteral key kept in the workspace file.
api_key_envone ofName of the environment variable holding the key. Wins over api_key when both are set.
weightno1 to 100, smooth weighted round-robin. Default 1.
quota_requestsnoCalls per endpoint per UTC day. 0 means no cap.
quota_tokensnoTokens per endpoint per UTC day. 0 means no cap.

On failure the endpoint is cooled down for 30 seconds, then 60, 120 and so on, capped at 600. The call moves to the next healthy endpoint within the same request. If every endpoint is down, cooled down or out of quota, the caller gets NoHealthyEndpoint and falls back to rule ordering.

The pool stores health and daily usage in the same JSON file. It does not store prompts or responses. llm_pool_records.jsonl keeps endpoint, model, purpose, token count, latency and the error string. audit.jsonl gets an llm.complete row for each success and each failure.

L3: what must be true before the loop runs

L3 is a lead pre-authorization with runtime edges, not a model with a shell. Preflight refuses unless all of the following hold:

  1. Consent is signed and the HMAC verifies. A missing or edited record stops here.
  2. The technical level is the top one, full-impact demo. Exploit verification and below are

refused.

  1. autonomy/grant.json exists, carries an HMAC over every field, is active and has not expired.
  2. --preauth-token matches token_sha256 in constant time. The default TTL is 1800 seconds.

inkblade autonomy revoke marks the grant revoked; the next preflight fails.

  1. The allowlist is not empty. max_actions is 1 to 50, max_steps is 1 to 20, and all four

budgets (tokens, latency, approvals, interventions) are positive. Zero is rejected: a budget of zero is not "unlimited".

  1. With --llm, a real endpoint exists. No endpoint means refusal at startup, not a silent

drop to rules.

At run time the guard checks every action against the allowlist, refuses writes unless --allow-writes was granted, rechecks namespace/host scope, pre-charges the budget before the action, enforces one per-step action cap, and stops after two consecutive failures. Write modules still pass the runner's backup gate; the grant does not replace it.

Each step appends autonomy.* audit rows and a trace row carrying plan_sha256 over the decision surface. inkblade autonomy replay replays those decisions without executing modules. To run again, issue a new grant.

inkblade autonomy grant --workspace l3-lab --role lead \
  --allowlist rbac-mapping,network-policy-coverage,escape-primitives \
  --max-actions 4 --max-steps 3 --ttl-seconds 1800 \
  --budget-tokens 20000 --budget-latency-ms 120000 \
  --budget-approvals 6 --budget-interventions 2

inkblade explore autonomy --workspace l3-lab --autonomy L3 \
  --llm --preauth-token '<token printed once>' --workers 2

inkblade autonomy status --workspace l3-lab
inkblade autonomy revoke --workspace l3-lab --reason "window closed"

Data boundary

A prompt can contain candidate module keys, product names, asset counts, eligible chain ids, the RoE level, and the blackboard summaries a lead pinned: finding title, severity, evidence anchor, asset key, product, address and note. report-ctem sends a small facts dictionary: run name, counts, module series, asset count, retest count.

It does not send credentials, service-account tokens, request or response bodies, evidence archives, context.jsonl.gz content, report bodies or API keys. Audit records carry endpoint id, model, token count and latency, not prompt text.

Use a local endpoint, or one your security team has approved for this data. Keep TLS for anything that is not on the same host. Put the key in an environment variable through api_key_env and keep it out of the repository. If you do use api_key, remember that the workspace file now holds a secret.

What changes without a model

If you want the deterministic path every time, pass --use-llm false to explore propose, or leave both the file and the environment unset. L3 without --llm never calls a model.

中文

扫描本身不需要模型

侦察、模块执行、链规划、证据、导出、报告正文，全部只依赖 Python 标准库。这条路径不加载权重、不连推理服务、也不要 key。断网的笔记本和配好端点的机器，产出的计划、证据树与报告是同一份。

接上模型以后，它只对规则引擎已经给出的候选做排序。它不能新增模块、放大范围、降低技术级别，也不能批准动作。

会调用模型的三处

路径模型做什么没有端点时
explore propose对确定性规划器给出的候选排序，最多返回 5 个模块 key规则排序：只读在前、有资产目标在前
explore autonomy --autonomy L3在预授权循环里做同样的排序带 --llm 时预检直接拒绝；不带则按规则跑
report-ctem依据 facts 字段写一段可选叙述固定模板段落

其余的 collect、discover、单模块、链、备份、回滚、三层证据、报告主体、SARIF/OCSF/VEX 导出、规则生成，都不出网。

两种接法

模型池 llm_pool.json。 支持多端点、权重、端点级配额、冷却与失败切换。explore 在池开启时优先用它。开启方式有两种：文件里 "enabled": true，或环境变量 INKBLADE_LLM_POOL=1。

环境变量接单端点。 INKBLADE_LLM_BASE_URL、INKBLADE_LLM_API_KEY、INKBLADE_LLM_MODEL。 explorer 与 L3 预检会读它们。这条路径没有权重、配额和健康记录，也不会被误开：不设 base URL 就不调用。两者同时存在时，先试池，失败再走环境端点。

export INKBLADE_LLM_API_KEY_LOCAL='<口令>'
export SCHEME=https                # 只有回环地址才用明文协议

# 加一个端点，再打开池（需要 lead 或 admin）
inkblade --home ./lab llm-pool add --workspace local-lab --role lead \
  --base-url "$SCHEME://127.0.0.1:8000/v1" \
  --model local-instruct \
  --api-key-env INKBLADE_LLM_API_KEY_LOCAL \
  --weight 1 --quota-requests 200 --quota-tokens 200000

inkblade --home ./lab llm-pool enable --workspace local-lab --role lead
inkblade --home ./lab llm-pool health --workspace local-lab --role lead

$SCHEME 在 TLS 网关上是 https，只有回环地址才用 http。add 只写端点，不打开池；enable 才打开。health 会对每个启用端点发 GET /models，池未开启时拒绝执行。

llm_pool.json 字段

CLI 把它写到 <home>/evidence/<workspace>/llm_pool.json。手改也可以，每次调用都会重新读。最小示例：

{
  "enabled": true,
  "endpoints": [
    {
      "id": "ep-01",
      "base_url": "<scheme>://127.0.0.1:8000/v1",
      "model": "local-instruct",
      "api_key_env": "INKBLADE_LLM_API_KEY_LOCAL",
      "weight": 1,
      "quota_requests": 200,
      "quota_tokens": 200000
    }
  ]
}
字段必填含义
enabled是总开关。缺失或 false 时，complete 一律抛 PoolDisabled。
endpoints[].id否稳定名称；省略时按 ep-01、ep-02 生成。
base_url是OpenAI 兼容根地址。主机部分是 127.0.0.1:8000/v1；加载器不接受没有传输协议的写法，所以 <scheme> 要换成网关实际使用的协议。
model是请求体里的模型名。
api_key二选一明文 key，落在工作区文件里。
api_key_env二选一存 key 的环境变量名。两者都在时以它为准。
weight否1 到 100，平滑加权轮询。默认 1。
quota_requests否每端点每 UTC 日请求数，0 表示不限。
quota_tokens否每端点每 UTC 日 token 数，0 表示不限。

端点失败后冷却 30 秒，随后 60、120 秒递增，上限 600 秒。同一次调用内切到下一个健康端点；全部不可用时抛 NoHealthyEndpoint，调用方降级到规则排序。

池把健康状态与当日用量写回同一个 JSON，不保存提示词与响应。llm_pool_records.jsonl 只存端点、模型、用途、token 数、时延与错误串。audit.jsonl 每次成功或失败都追加一行 llm.complete。

L3 的前置条件

L3 是 lead 预授权加运行时硬边界，不是给模型一个 shell。以下任一条不成立，预检就拒绝：

  1. 授权已签且 HMAC 验签通过。记录缺失或被改动，到这里就停。
  2. 技术级别是最高级「全影响演示」。「利用验证」及以下直接拒绝。
  3. autonomy/grant.json 存在，HMAC 覆盖全部字段，status 为 active，且未过期。
  4. --preauth-token 与 token_sha256 常量时间比对通过。默认 TTL 1800 秒。inkblade autonomy revoke

把 grant 标成 revoked，下一次预检即失败。

  1. 白名单非空；max_actions 1 到 50，max_steps 1 到 20；tokens、latency、approvals、interventions

四项预算都必须为正。写 0 会被拒：预算为 0 不等于「不限」。

  1. 带 --llm 时必须存在真实端点。没有端点就在启动时拒绝，不静默降级。

运行时，护栏逐个动作检查白名单；未授权 --allow-writes 时拒绝写动作；复核 namespace/host 范围；动作前预扣预算；限制单步动作数；连续两次失败即停。写模块照旧过 runner 的备份闸门，grant 不能替代它。

每一步都会写 autonomy.* 审计行，以及带 plan_sha256 的 trace。inkblade autonomy replay 只重放决策，不执行模块。要再跑一次，只能签发新 grant。

inkblade autonomy grant --workspace l3-lab --role lead \
  --allowlist rbac-mapping,network-policy-coverage,escape-primitives \
  --max-actions 4 --max-steps 3 --ttl-seconds 1800 \
  --budget-tokens 20000 --budget-latency-ms 120000 \
  --budget-approvals 6 --budget-interventions 2

inkblade explore autonomy --workspace l3-lab --autonomy L3 \
  --llm --preauth-token '<只显示一次的 token>' --workers 2

inkblade autonomy status --workspace l3-lab
inkblade autonomy revoke --workspace l3-lab --reason "窗口结束"

数据边界

提示词里可能出现：候选模块 key、产品名、资产数量、成立的链 id、RoE 级别，以及 lead 固定到黑板的摘要（发现标题、严重度、证据锚点、资产 key、产品、地址、备注）。report-ctem 会发一个很小的 facts 字典： run 名、各项计数、模块系列、资产数、复测数。

不会发送：凭据、ServiceAccount 令牌、请求或响应正文、证据归档、context.jsonl.gz 内容、报告正文、 API key。审计只记端点、模型、token 数与时延，不记提示词。

端点用本地的，或者安全团队为这类数据批准过的。不在同一台主机上就上 TLS。key 放环境变量，通过 api_key_env 引用，不要进仓库。如果确实用了 api_key，就把工作区文件当成密件。

没有模型时差在哪

行为有端点没有
候选顺序模型排序，并按候选集校验；集外 key 丢弃固定规则顺序
提议模式模型给出可用序列时记 llm记 rules，不报错
报告叙述模型写的一段模板段落
带 --llm 的 L3运行预检拒绝
不带 --llm 的 L3规则排序循环相同
配额与审计llm.complete 行与端点计数无

想始终走确定性路径，就给 explore propose 加 --use-llm false，或者文件和两个环境变量都不设。不带 --llm 的 L3 不会调用模型。
