Pilot kit - running InkBlade on a real cluster

A pilot is bounded, authorized and read-first. Scope: one cluster (or one namespace set), one window, 1–2 testers, 5–10 working days. Copy this into your change record; do not run from memory.

1. Roles

Two-person rule above probe: someone who is not driving watches the run.

2. Authorization pack

Without a pinned, signed RoE the CLI exits 91 and the API returns 423 Locked. The RoE carries a SHA-256 of its canonical fields plus an HMAC bound to the workspace key.

2.2 Levels

LevelCanonical valuePermitted activityWrite risk

Level is a ceiling: modules with a higher min_level refuse to run, and raising it needs a new signed RoE.

consent.json lands next to evidence.db. Archive it with the report.

FP needs a refutation artefact; a missing artefact is inconclusive, never TP. FN is recorded against the module that should have caught it, so the gap becomes a regression test.

6. Exit criteria

#Criterion
1every approved module executed, skipped with a recorded reason, or excluded by the customer
2every finding has an evidence reference and a human label
3report, remediation list, rules pack and archive delivered and acknowledged
4rollback confirmed for any write activity
5data handling executed (retention or destruction)
6retrospective written

6.1 Go / no-go

CriterionThreshold
False positives≤ 20%, all with refutation artefacts
Evidence completeness100% of confirmed findings
Incidents caused0
Operator effort≤ 1 person-hour per confirmed high+
Critical-surface coverage≥ 60%, or gaps accepted in writing

Any failed row means "pilot again with scoped changes", not "adopt".

7. Stop conditions

TriggerAction
A write lands outside declared namespaces/CIDRsstop, preserve evidence, notify
A finding suggests data outside scope (weights, PII, secrets)stop, preserve, notify
Control-plane or GPU-operator health degradesstop
RoE window expires mid-runfinish the current step, export, re-sign
Anyone is unsure the activity is authorizedstop

Incident path: observer → sponsor → legal/DPO. Preserve evidence.db and steps/ before cleanup.

8. Offboarding

#Step
1export the evidence bundle, record its SHA-256 in the handover ticket
2destroy the workspace copy after the RoE retention period
3rotate credentials used during the pilot
4remove the ServiceAccount/RBAC and the Helm release
5confirm deletion in writing, attach it to the report
