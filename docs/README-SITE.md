# Site source and publishing / 站点源码与发布

[English](#english) · [中文](#中文)

This is a maintainer note, not product documentation. It explains how the pages in `docs/` are
generated, what gets published, and how to check the result before pushing.

---

## English

### Layout

```
docs/
├── index.html          bilingual landing page (language toggle, no reload)
├── en/index.html       English-only page
├── zh/index.html       Chinese-only page
├── assets/style.css    the only stylesheet
├── assets/app.js       language switch, scroll spy, copy buttons
├── .nojekyll           keep the hosting platform from reprocessing the tree
└── *.md                public guides linked from the pages
```

Every page is generated by `scripts/build-docs-site.py`. Edit the generator, not the HTML —
`--check` fails when the committed output is stale.

```bash
python scripts/build-docs-site.py
python scripts/build-docs-site.py --check
python scripts/check-docs-links.py
```

### What gets published

The publishing workflow stages an allowlist into `_site/` and uploads that. The published set is:

- `index.html`, `en/`, `zh/`, `assets/`, `.nojekyll`
- the public guides: `USAGE`, `INSTALL`, `FEATURES`, `WORKFLOW`, `MODULES`, `FAQ`, `0DAY-PUBLIC`,
  `ARCHITECTURE`, `README-SITE`
- nothing else

Internal research and vendor-report material stays out of the artifact on purpose. Those
directories are not part of the public documentation and should not be served from a public
site, even when they happen to live under the same repository.

### Why not point Pages at `docs/` directly

You can — `Settings → Pages → Deploy from a branch → /docs` — and for a small tree it is fine.
It also publishes every Markdown file in `docs/`, including design notes and lab records. The
allowlist workflow exists so a public URL never becomes a shortcut to material that is waiting
for a coordinated disclosure.

If you prefer the branch setting, move or exclude the internal documents first, then set it.
Don't do both at once and assume the workflow wins; check what the deployed URL actually serves.

### Local preview

Open `docs/index.html` in a browser. Everything is relative and local: no fonts, no CDN, no
analytics, no requests to any third party.

For a closer approximation of the host (absolute paths, directory indexes):

```bash
python -m http.server 8000 --directory docs
```

Then open the local address it prints. Stop the server when you are done.

### Rules the pages follow

- No absolute URLs anywhere: no anchors, no `src`, no CSS `url()`, no `@import`.
- No drive letters, user names, internal archive paths, private addresses or host names.
- Cross-references stay relative and resolve inside `docs/`.
- The 0-day section lists component, class, affected versions, status and disclosure window.
  It contains no runnable code, no request bodies and no root-cause location.

`scripts/check-docs-links.py` enforces the first and third rules mechanically. Run it before
every push; it is cheap and it catches the mistakes humans make at 1 a.m.

## 中文

### 目录结构

```
docs/
├── index.html          双语首页（语言切换，不刷新）
├── en/index.html       英文页
├── zh/index.html       中文页
├── assets/style.css    唯一的样式表
├── assets/app.js       语言切换、目录高亮、复制按钮
├── .nojekyll           让托管平台不要重新处理这棵树
└── *.md                页面引用的公开指南
```

所有页面由 `scripts/build-docs-site.py` 生成。改生成器，不要改 HTML——提交产物过期时 `--check` 会失败。

```bash
python scripts/build-docs-site.py
python scripts/build-docs-site.py --check
python scripts/check-docs-links.py
```

### 发布哪些文件

发布工作流把白名单拷进 `_site/` 再上传。发布集合是：

- `index.html`、`en/`、`zh/`、`assets/`、`.nojekyll`
- 公开指南：`USAGE`、`INSTALL`、`FEATURES`、`WORKFLOW`、`MODULES`、`FAQ`、`0DAY-PUBLIC`、
  `ARCHITECTURE`、`README-SITE`
- 别的都不发

内部研究与厂商汇报材料刻意不进产物。它们不属于公开文档，即使物理上放在同一个仓库里，也不该由公开站点提供。

### 为什么不直接把 Pages 指到 `docs/`

可以——`Settings → Pages → Deploy from a branch → /docs`——目录小的时候没问题。但它会把 `docs/` 下每一个
Markdown 都发布出去，包括设计笔记与实验记录。白名单工作流存在的意义，是避免某个公开 URL 变成通往“等协调披露的材料”
的捷径。

如果你更想用分支设置：先把内部文档移走或排除，再设置。不要两边都开还假设工作流会赢——去看部署后的 URL 实际返回什么。

### 本地预览

用浏览器打开 `docs/index.html`。全部相对路径、全部本地：没有字体、没有 CDN、没有统计、没有任何第三方请求。

想更接近托管环境（绝对路径、目录索引）：

```bash
python -m http.server 8000 --directory docs
```

打开它打印的本地地址，用完记得停掉。

### 页面遵守的规则

- 不出现绝对 URL：没有外链、没有 `src`、没有 CSS `url()`、没有 `@import`。
- 不出现盘符、用户名、内部归档路径、私有地址或主机名。
- 交叉引用一律相对路径，并且能在 `docs/` 内解析。
- 0day 章节只列组件、类别、受影响版本、状态与披露窗口，不含可执行代码、请求内容或根因位置。

`scripts/check-docs-links.py` 会把第一条和第三条机械地查一遍。每次推送前跑一下；很便宜，而且能抓到凌晨一点常犯的错。
