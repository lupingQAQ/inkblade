02

Install and run

Requirements, then four commands

No cluster. No kubeconfig. No API key. Mock targets bind to loopback. Writes stay in the output directory.

Requirements

  • Python 3.10 – 3.13 on PATH. No compiler, no virtualenv, no third-party package.
  • 200 MB disk for demo workspace, reports, console.
  • Optional: Docker 24+, Helm 3, a kubeconfig for later.

Four commands

  1. python -m pip install -e .Entry point. Or use python -m inkblade ....
  2. python -m inkblade doctorPython, writes, ports, deps, cluster reachability. Under a second.
  3. python -m inkblade demoWorkspace, consent, mock lab, 2 modules, 1 chain, reports. 4–5 s.
  4. python -m inkblade trialSame run, shorter output, plus next steps.
terminal · offline demo
$ python -m inkblade doctor
$ python -m inkblade demo
$ python -m inkblade trial

Other ways in

container
docker build -t inkblade:0.2.0 .
docker run --rm -v inkblade-data:/data inkblade:0.2.0 trial
helm · read-only by default
helm install inkblade deploy/helm/inkblade --namespace inkblade --create-namespace

uid 10001, read-only root, /data writable. Chart grants get/list/watch. Writes need two switches and a signed record; otherwise HTTP 423.

03

Test a cluster safely

Pilot first, read-only by default, backup before writes

Gates, in order. Each one stops the run. First pass is read-only.

  1. inkblade pilotRead-only inventory: namespaces, workloads, GPU capacity, gateways, storage. Profile, heat map, approval list.
  2. inkblade roe / quickstartScope, level, window, signed. No record, no run.
  3. Read-only modules191 of 286. Enumerate and confirm. No state change.
  4. execute --dry-runGraph, preconditions, every write. Nothing runs.
  5. Approve and back upWrite modules need both. Missing one exits 91.
  6. inkblade rollbackStep back, report what will not return. Failed restore is a finding.
GateRefuses whenSignal
ConsentNo record, expired window, out-of-scope asset.exit 91 / HTTP 423
LevelModule level above the record.exit 91
BackupWrite module, no writable target.exit 91
SurfaceMissing surface, no --probe.skipped, recorded
RollbackA step cannot be restored.exit 3

Demo stays on loopback. Writes stay in the workspace. Real clusters need a signed record and a kubeconfig.

Emergency stop: inkblade abort. Release with --clear.

04

Full workflow

Eleven stages, from signature to retest

Eleven stages. Each leaves something the next can check.

11stages
3evidence layers per step
2report languages
0actions without a record
  • 01AuthorizationSigned consent with scope, window, level and emergency contact. The hash rides along in every run.
    → consent record + hash
  • 02AssetsSeeds grow into an incremental asset table; imported scanner results are normalised into the same inventory.
    → assets table, collection snapshot
  • 03ReconnaissanceRead-only modules look at what is really deployed. The surface matrix says what is testable here.
    → findings, surface matrix
  • 04CombinationDeclared combination signatures pull out findings that only matter together, preconditions attached.
    → ranked combinations
  • 05Chain planningChains are ordered graphs. Dry-run resolves the topology and prints every write before it happens.
    → plan, write surface
  • 06ApprovalHigh-impact steps wait for a human, or for a bounded pre-authorisation with an explicit level.
    → approval record, window
  • 07ExecutionOnly the approved scope runs. Write modules pass the backup gate first; refusals exit 91.
    → action log, backups
  • 08EvidenceContext journal, SQLite audit tables, one archive per step with a SHA-256 manifest.
    → context.jsonl.gz, evidence.db, steps/
  • 09ReportPentest narrative and remediation checklist from the same evidence, in Chinese and English.
    → reports, SARIF, OCSF, VEX
  • 10RulesEach chain becomes admission, network, detection and convergence rules, then gets replayed.
    → rule packs, replay matrix
  • 11RetestScheduled re-runs are diffed against the baseline. Drift is a finding; silence is not a pass.
    → drift report, pipeline verdict

Stage five is where most tools start. Here it needs a record, inventory, surface matrix and plan first. A refusal stops the run.

Limits and responsible use

What this is not, and where authorization is not negotiable

Coverage is uneven

Kubernetes 60–71%. Slurm 25%. Missing modules listed per profile.

Verification is partial

37 of 152 entries have a dynamic run. 6 more exposure-verified. Rest are hypotheses.

Reserve row is a lead

One commit, one config. Patch level decides exposure.

Autonomy is bounded

Planner and explorer exist. Default: propose and wait.

No telemetry

No outbound calls unless enabled. No licence server.

Pre-1.0

Interfaces move. Pin a version for a regulated pilot.

Authorized use only. Written authorization or nothing. Testing systems you do not own is a crime in most jurisdictions. The software refuses without a signed record.

Issues in InkBlade: private vulnerability reporting, 90-day target. No public issues with exploit detail.

AI-generated content disclosure

How these pages were written

Parts of this site and the READMEs were drafted with AI assistance. A human maintainer ran the commands, checked the numbers against code and reports, and cut claims that would not reproduce.

Detectors disagree with each other and with people. No detection rate is quoted. Sentences that read like a machine wrote them probably started that way. Numbers that look wrong are bugs.

Code, manifests, rule packs and evidence come from the software. This covers prose.
