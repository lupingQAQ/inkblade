Platform capabilities

  • One execution path. Foothold, Rust probe, framed channel, in-pod task, child probe, evidence.
  • Zero target-side interpreter. A static binary runs the same templates on distroless, scratch and Python images.
  • Probe trees. probe_id and parent_id, per-child tokens, stricter inheritance, bounded depth and fan-out, child-first cleanup.
  • Agent runtime. A budgeted objective graph with decision trace, journal resume and zero-execution replay.
  • Cross-cluster relay. The same framed protocol between clusters, with a closure proof.
  • Evidence at the boundary. Task results, step logs, artifacts, SHA-256 manifests, traffic tables and cleanup receipts.
  • Rules you can replay. Admission, runtime and network packs with blocked / detected / missed matrices.
  • Report and console. Bilingual pentest and remediation reports, SARIF / OCSF / VEX export, local console.
  • No telemetry. No account, cloud key or licence server; no outbound call unless configured.
02

One execution path

Three planes, one probe tree

The controller never executes target-side logic. It authorizes, renders templates, enforces budgets and archives evidence. The probe is the only code that runs inside the Pod.

execution path
foothold ──▶ Rust probe ──▶ framed channel ──▶ in-pod task
                                              │
                                              ├─▶ child probe ──▶ child probe
                                              └─▶ evidence ──▶ report / rules / console

Three planes

  • Template plane. template.json declares inputs, payloads, steps, computed state, checks, findings and artifacts.
  • Probe plane. A static Rust binary speaks an HMAC-authenticated framed protocol and executes http, tcp, exec, fs, k8s, socks and spawn ops.
  • Control plane. Python enforces consent, scope, level, backup and audit, then folds probe evidence into findings.

Probe tree

Every probe has a probe_id and a parent_id. Children inherit the parent's read-only state, command allow-list and budget, and can only be stricter. Cleanup is child-first, so no orphan keeps a token alive.

03

From foothold to report

Nine stages, each leaves something the next can check

The order is the product. Any stage can refuse; a refusal stops the run.

  • 1Footholdsession open records the entry vector, target, namespace, Pod and credential fingerprint.
    → session record
  • 2Rust probeprobe deploy delivers the static binary and registers its identity and hash.
    → probe identity
  • 3Channelchannel start carries the framed protocol and exposes loopback SOCKS5 and forwards.
    → channel state
  • 4Detectionsession run, run and agent run execute templates across the ten layers.
    → findings, evidence
  • 5Escapeexecute resolves a chain; write steps pass the backup gate first.
    → escape path
  • 6Lateralchannel forwards, child probes and agent graph edges map internal reachability.
    → reachability graph
  • 7Multi-probeprobe spawn extends the tree; children inherit a stricter budget and allow-list.
    → probe tree
  • 8Cross-clusteragent relay connects clusters; agent coverage writes the closure proof.
    → relay status, coverage proof
  • 9Report / rules / consolereport, export, rules generate and ui close the engagement.
    → report, rule packs, console

04

Real environment, five steps

Install, authorize, deliver, run, report

Run against a cluster you are authorized to test.

  1. python -m pip install -e .Install the controller. Python 3.10 – 3.13, no compiler.
  2. python -m inkblade upOnboarding wizard: workspace, authorization, kubeconfig.
  3. python -m inkblade quickstartSign the record: target, scope, level, window.
  4. python -m inkblade session open --mode kubeconfig ...Bind the target and open the session.
  5. python -m inkblade probe deploy --via kubectl ... --allow-writeDeliver the static probe and register it.
terminal · authorized cluster
$ python -m inkblade up
$ python -m inkblade quickstart
$ python -m inkblade session open --mode kubeconfig --workspace ./work     --kubeconfig ~/.kube/config --namespace ml-team --pod infer-0
$ python -m inkblade probe deploy --session <session-id> --via kubectl     --binary ./inkblade-probe-linux-amd64 --namespace ml-team --pod infer-0 --allow-write
$ python -m inkblade agent run --probe <probe-id> --objective read-only-recon --workspace ./work
$ python -m inkblade report --run <run-id> --lang bi

agent run prints the run_id consumed by report. Writes need the signed record and --allow-write; without it, probe deploy prints the plan.

Wheel, container, Helm

One controller, any of three delivery paths

The controller is a Python package with no third-party dependency. The probe is a separate static binary.

wheel
python -m pip wheel . --no-deps -w dist/
python -m pip install --no-index --find-links dist/ inkblade
container
docker build -t inkblade:0.2.0 .
docker run --rm -v inkblade-data:/data inkblade:0.2.0 up
helm · read-only by default
helm install inkblade deploy/helm/inkblade   --namespace inkblade --create-namespace

uid 10001, read-only root, a PVC for evidence. Read verbs by default; writes need readOnly=false, rbac.allowWrite=true and a signed record. Uninstall keeps the PVC.

07

Security and authorization

Authorization is a prerequisite, not a feature toggle

InkBlade refuses to run without a signed record. Every stage keeps its own gate.

  1. RoE recordTarget, scope, level, window and emergency contact. Hash-pinned and carried by every run.
  2. Read-only defaultCollection, probes, file reads and read-only templates need no extra flag.
  3. Five write gatesSession level, --allow-write, meta.writes, backup-write mode, backup receipt.
  4. Backup and rollbackSnapshot before the write, record both, restore one step at a time.
  5. Audit and evidenceEvery probe action and file access lands in the evidence store with a SHA-256 manifest.
  6. Kill switchinkblade abort stops the workspace; agent stop stops one run.
ControlWhat it guarantees
Consent hashThe authority for a run is one file, not a meeting.
Scope and levelOut-of-scope or above-level actions are refused before execution.
Backup receiptNo write without a restorable snapshot.
Evidence manifestEvery finding resolves to a task, step, artifact, probe or manifest hash.
No telemetryNothing leaves the workspace unless you enable an integration.

Authorized use only. Written authorization or nothing. Testing systems you do not own is a crime in most jurisdictions. The software refuses without a signed record.

Report security issues through the private channel in SECURITY.md. Do not open a public issue with exploit detail.

08

FAQ

Access, probe, detection, authorization, delivery

Does the target Pod need Python?

No. The probe is a static Rust binary and templates are JSON. The Pod needs a Linux kernel, a writable temporary directory or memfd_create, and the probe process inherits the Pod's namespaces and service account.

How does the probe get into the Pod?

kubectl, a ServiceAccount token, a shared volume, an EphemeralContainer manifest or an authorized RCE callback. Each path has prerequisites and leaves traces.

Is the probe a backdoor?

No. It does not persist, modify startup, patch images or call a fixed C2. It runs inside an authorized session, executes registered templates, defaults to read-only, gates writes and cleans up.

Will HIDS or EDR see it?

Yes. The probe does not hide processes, connections or file writes. Layer 10 measures whether defenders see benign markers; it does not provide evasion.

How are writes controlled?

Five gates: signed authorization covering target/level/window, --allow-write, meta.writes with a write step, backup-write mode and a backup receipt. A write reads back the hash and rolls back on failure.

Can it run air-gapped?

Yes. The controller needs no network, the probe needs no package index, and templates and rule packs ship with the release.

Does it phone home?

No. There is no account system, licence server or telemetry. Optional integrations stay off until configured.

Can I use it commercially?

Apache-2.0 permits commercial use and forks. Keep LICENSE and NOTICE, and do not use the InkBlade trademark for a fork.
