# Trident SOTA-2026-10 能力矩阵与差距

> 基线日期：2026-10-25。参照来源以本仓库 [`trident/arch-intel/corpus/`](../trident/arch-intel/corpus/)
> （35 源、2026-10-25 逐源核验）与各标准/产品官方文档为准。矩阵描述**本仓库当前实现与测试证据**，
> 不把 fixture、脚本交付或公开资料阅读等同于现场实跑。

## 判定口径

- **已达成**：仓库内可复现实现 + 自动化测试（或可重复 e2e/实效脚本）覆盖；无外部环境前置。
- **部分**：接口、解析或规划已实现并有测试，但缺真实环境/生产信任链/真实对手数据。
- **未达成**：仅有设计、脚本或公开资料对照，没有任何可复现的实测数据；不写成「已支持」。

## 计数

**已达成 26 · 部分 7 · 未达成 5**（共 38 项能力）。

> 2026-10-25 收尾批次变化：新增「输出确定性」「执行审计轨迹」两行（已达成）；
> 「多租户」拆为「单机隔离与有界并发」（已达成）+「分布式调度/跨副本配额」（未达成）；
> 「Live K8s」由部分转已达成（QEMU k3s 真集群 + hostNetwork 旁路实证）；
> 「真实 ARTEX 对比数据」由未达成转部分（同靶场 + 全端点网格已实测，但仍为 QEMU TCG 软件仿真）。

## Ruling 与边界

1. **fixture ≠ 生产证据**：供应链与 TEE 的签名/证明均为本地 fixture；报告与 SOTA 均显式标注
   「部分/未达成」，不得把 fixture 通过当作硬件或生产信任链通过。
2. **规划 ≠ 执行**：`agent_planner` 与 MCP `get_chain_plan` 只输出计划；审批角色固定 lead，
   `execution.trigger=human`、`performed=false`；测试锁定零 actions 写行。
3. **合规映射 ≠ 认证结论**：七框架映射是多标签工程归类，未命中具体类别时使用平台面兜底条款；
   官方文本优先。
4. **corpus 是公开基线**：35 源均记录核验日期/方法/缺口（见 `coverage-matrix.json` 的 notes），
   不把厂商文档阅读等同于现场实测。
5. **效果级 ≠ 集群级**：本机真实进程/HTTP 的效果验证与 live K8s 集群验证分开陈述；QEMU TCG
   下的绝对性能值不作为产品级性能结论。
