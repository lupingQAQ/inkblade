Usage / 使用手册

English · 中文

English

A workspace is a directory: user file, consent record, asset inventory, one evidence tree per run. --home (or --workspace) points at it and nothing else is read.

python -m inkblade ... and inkblade ... are the same program. Every flag belongs to a subcommand, so inkblade run --help is the reference for run.

1. Workspace and people

python -m inkblade user add alice '<password>' lead
python -m inkblade user add bob '<password>' tester
python -m inkblade user add carol '<password>' auditor
python -m inkblade roe

lead approves. tester executes inside an approved scope. auditor reads evidence and runs nothing. admin manages the workspace. Skip this and nobody can approve a high-impact step later.

2. Sign first

python -m inkblade quickstart

Five questions, then a consent record with a hash that is stamped into every run. Levels are cumulative: read-only recon, active probing, exploit verification, full-impact demo. A level-3 module under a level-2 record does not run — no --force, no env var.

3. Inventory, then look

python -m inkblade pilot --kubeconfig ~/.kube/config --out pilot/
python -m inkblade collect --profile bare-k8s-gpu --out collection/
python -m inkblade surfaces --profile bare-k8s-gpu --collect collection/

pilot is read-only: profile, heat map, approval checklist. collect adds details. surfaces tells you whether the surface each module needs exists here at all.

4. One module

python -m inkblade run --module k8s-rbac-surface --role tester
ExitMeaning
0ran
91a gate refused
3rollback left something behind

Write modules need a backup target:

python -m inkblade run --module <write-module> \
  --params '{"namespace":"ml-team"}' \
  --backup-target ./backups/

5. Chains

python -m inkblade execute --chain <id> --dry-run
python -m inkblade execute --chain <id> --workers 2

The dry run prints order, dependencies, writes and preconditions. A false precondition stops the chain; a typo in the chain id fails immediately.

6. Evidence

LayerFileUse it for
Contextcontext.jsonl.gzWhat the tester saw, step by step.
Auditevidence.dbFindings, actions, backups, rollbacks.
Proofsteps/*.tar.gz + manifest.sha256Handing one step to someone else.

7. Report, export, defend

python -m inkblade report --run <id> --kind pentest --lang bi
python -m inkblade export --run <id> --format sarif --out findings.sarif
python -m inkblade rules generate --out rules/ --cni cilium

Two renderings of one evidence tree, so they cannot disagree. --redact strips deep detail before a report leaves the team. rules validate replays each pack and reports blocked / detected / missed per chain.

8. Retest and CI

python -m inkblade schedule add --cron "0 3 * * 1" --chains <ids>
python -m inkblade schedule run-due
python -m inkblade ci-gate --run <id> --fail-on high --new-only

9. Embedding

inkblade mcp exposes read-only tools over stdio. inkblade plan proposes; a lead still approves. The plugin SDK is for modules in your repository, pinned by SHA-256 fingerprint — no auto-trust path.

10. Agent and LLM (optional)

Nothing in sections 1 to 9 needs a model. If you want one, add it to the workspace pool and switch the pool on:

export INKBLADE_LLM_API_KEY_LOCAL='<token>'
export SCHEME=https                # plaintext scheme only on loopback
python -m inkblade llm-pool add --workspace local-lab --role lead \
  --base-url "$SCHEME://127.0.0.1:8000/v1" --model local-instruct \
  --api-key-env INKBLADE_LLM_API_KEY_LOCAL --quota-requests 200
python -m inkblade llm-pool enable --workspace local-lab --role lead
python -m inkblade llm-pool status --workspace local-lab
python -m inkblade llm-pool health --workspace local-lab --role lead

$SCHEME is https for a TLS gateway, http only on loopback. The pool file lives at <home>/evidence/<workspace>/llm_pool.json. With no endpoint, explore propose orders candidates by rules and sets mode: rules.

L3 is opt-in and takes more than an endpoint: inkblade autonomy grant issues a lead token with a TTL, a module allowlist and four budget caps, then explore autonomy --autonomy L3 runs the loop with that token. Writes stay off unless granted, and the guard stops after two consecutive failures. Fields, data boundary and failure behaviour: Agent & LLM.

中文

工作区就是一个目录：用户文件、授权记录、资产清单，以及每次 run 的一棵证据树。用 --home（多数子命令也用 --workspace）指过去，工具不会去别处找。quickstart 会建一个并引导你填写范围；真实试点通常从 pilot --kubeconfig 开始。

看命令表之前先记住两件事。第一，python -m inkblade ... 和 inkblade ... 是同一个程序，短命令要先 pip install -e .。第二，参数属于子命令，inkblade run --help 才是 run 的准确说明。下面的表覆盖九成日常。

1. 先建工作区和人

python -m inkblade user add alice '<口令>' lead
python -m inkblade user add bob '<口令>' tester
python -m inkblade user add carol '<口令>' auditor
python -m inkblade roe

角色不是装饰。lead 审批，tester 在批准范围内执行，auditor 只能读证据、不能执行，admin 管工作区。跳过这步 CLI 照样能用，但之后没人能批准高影响步骤。

2. 先签授权，再谈其他

python -m inkblade quickstart

五个问题：目标、范围、技术级别、用户、签署。答完得到一份带哈希的授权记录，哈希会写进后续每一次 run。记录丢了这个洞就永远在。

别把它当勾选项。级别是累进的，且由工具强制执行：只读侦察、主动探测、利用验证、全影响演示。需要 3 级的模块在 2 级授权下不会跑。没有例外，没有 --force。

3. 先清点，再看

python -m inkblade pilot --kubeconfig ~/.kube/config --out pilot/
python -m inkblade collect --profile bare-k8s-gpu --out collection/
python -m inkblade surfaces --profile bare-k8s-gpu --collect collection/

pilot 天生只读，产出部署画像、模块族适用热图，以及可以直接交给平台负责人的审批清单。collect 补细节。 surfaces 再逐个模块告诉你：要的面到底在不在——生产可测、有条件、还是根本没有。

最后一列很省时间。对着托管控制面硬跑四十个根本不适用的模块，不叫全面，叫噪音。

4. 跑一个模块

python -m inkblade run --module k8s-rbac-surface --role tester

看退出码，不要只看文字。0 是跑完了，91 是闸门拒绝，3 是回滚有遗留。拒绝会点名是哪道闸门、怎么修。那不是崩溃，是产品在工作。

写类模块要带备份目标：

python -m inkblade run --module <写类模块> \
  --params '{"namespace":"ml-team"}' \
  --backup-target ./backups/

没有 --backup-target 就在闸门前停下。这是故意的。我们没见过后悔做备份的团队，倒是见过不少后悔没做的。

5. 链

python -m inkblade execute --chain <id> --dry-run
python -m inkblade execute --chain <id> --workers 2

dry-run 会打印解析后的链图：哪个模块先跑、每步依赖什么、哪些步骤会写、哪些前置条件必须已成立。读它。前置条件不成立时链会停在那里，而不是即兴发挥。

链 id 在 inkblade/chains/*.json 里。--chain 写错时立即失败、什么都不列——这是你对拼写错误的合理期待。

6. 证据

每次 run 在 <工作区>/evidence/<run>/ 下留三层：

层文件用途
上下文context.jsonl.gz逐步还原测试者当时看到了什么。
审计evidence.db查询：发现、动作、备份、回滚。
证明steps/*.tar.gz + manifest.sha256把某一步交给别人，且可校验。

报告锚点是步骤哈希，不是段落。发现被质疑时，重放那一步，而不是争论。

7. 报告、导出、防守

python -m inkblade report --run <id> --kind pentest --lang bi
python -m inkblade report --run <id> --kind remediation --lang en
python -m inkblade export --run <id> --format sarif --out findings.sarif
python -m inkblade rules generate --out rules/ --cni cilium

渗透报告给防守方；修复报告给平台组，叙事更短。两者出自同一套证据，所以不会互相打架。报告需要离开项目组时，用 --redact 去掉深层细节。

规则包只有被测过才有用。rules validate 会对着 fixture 目标重放，给出每条链的拦截 / 检出 / 漏过。一条什么都拦不住的规则比没有规则更糟：它看起来像覆盖率。

8. 复测与门禁

python -m inkblade schedule add --cron "0 3 * * 1" --chains <ids>
python -m inkblade schedule run-due
python -m inkblade ci-gate --run <id> --fail-on high --new-only

schedule run-due 与基线做差异并报告漂移。ci-gate 把一次 run 变成退出码，让流水线能因为新增高危失败，而不会因为你已经接受的存量失败。

9. 嵌进别的系统

inkblade mcp 用 stdio 说 MCP，只暴露只读工具；inkblade plan 产出排序后的建议，但仍需 lead 审批。插件 SDK（sdk new、lint、validate、trust、run）是给放进你自己仓库的模块用的。信任是你显式接受的 SHA-256 指纹，没有自动信任通道。

10. Agent 与 LLM（可选）

第 1 到第 9 节都不需要模型。要接的话，先往工作区模型池加端点，再打开池：

export INKBLADE_LLM_API_KEY_LOCAL='<口令>'
export SCHEME=https                # 只有回环地址才用明文协议
python -m inkblade llm-pool add --workspace local-lab --role lead \
  --base-url "$SCHEME://127.0.0.1:8000/v1" --model local-instruct \
  --api-key-env INKBLADE_LLM_API_KEY_LOCAL --quota-requests 200
python -m inkblade llm-pool enable --workspace local-lab --role lead
python -m inkblade llm-pool status --workspace local-lab
python -m inkblade llm-pool health --workspace local-lab --role lead

$SCHEME 在 TLS 网关上是 https，只有回环地址才用 http。池文件在 <home>/evidence/<workspace>/llm_pool.json。没有端点时，explore propose 按规则排序，并把模式记成 mode: rules。

L3 要的不只是一个端点：inkblade autonomy grant 签发带 TTL 的 lead token、模块白名单与四项预算硬顶，再用 explore autonomy --autonomy L3 跑循环。写动作默认关闭，连续两次失败即停。字段、数据边界与失败行为见 Agent 与 LLM。

排障

现象多半是怎么办
run 退出 91没授权、级别不够、或没给备份目标先 inkblade roe，再 quickstart；补 --backup-target
rollback 退出 3有步骤恢复不了读回执；恢复不了的那一步本身是发现
找不到 inkblade装到了另一个解释器改用 python -m inkblade ...
