Module catalogue / 模块目录

English · 中文

286 manifests, 275 enabled by default, 11 quarantined. This page explains how the catalogue is organised and how to browse it on your own machine. The authoritative list is always the tree: inkblade/modules/<key>/module.json.

English

Browse it

python -m inkblade module list
python -m inkblade module list --modules-dir inkblade/modules
python -m inkblade surfaces --profile airgapped --fixture

module list prints key, series, technical level, read/write and required surface count per module. Add --json where the subcommand supports it when you want to feed a dashboard. surfaces answers a different question: of these modules, which ones can actually run against this deployment shape?

Chain files live in inkblade/chains/*.json. Each step names one module, optionally depends on earlier steps, and carries parameters. Preconditions use a small expression language — no eval and no arbitrary Python.

The manifest contract

{
  "key": "example-module",
  "series": "权限链",
  "min_level": "只读侦察",
  "writes": false,
  "requires": ["k8s-object:ClusterRole"],
  "combo_signature": ["example-combination"],
  "produces": ["findings"]
}

Fields that matter: writes triggers the backup gate; requires drives the surface matrix; min_level is checked against the consent record; combo_signature is what lets the platform say “these two findings are one problem”.

Quarantined modules

Eleven modules need a surface that none of the six reference profiles contains: agent-native control planes, two vendor runtime APIs, one hardware-only path. They stay in the tree because customers do deploy those things. They are excluded from coverage denominators and are never enabled by a profile.

Adding your own

python -m inkblade sdk new my-module
python -m inkblade sdk lint my-module
python -m inkblade sdk validate my-module

The SDK enforces a strict manifest profile, keeps the entry point inside the module directory, records a SHA-256 fingerprint you accept explicitly, and validates the result schema. There is no auto-trust: a plugin you have not fingerprinted will not run, even if it is on disk.

Submissions upstream need three things: a manifest, a dry-run path, and tests. Modules that only work against a live cluster are welcome, but they need a recorded fixture so CI can exercise them.

manifest 契约

{
  "key": "example-module",
  "series": "权限链",
  "min_level": "只读侦察",
  "writes": false,
  "requires": ["k8s-object:ClusterRole"],
  "combo_signature": ["example-combination"],
  "produces": ["findings"]
}

关键字段：writes 触发备份闸门；requires 驱动部署面矩阵；min_level 对着授权记录检查； combo_signature 让平台能说“这两条发现其实是同一个问题”。

隔离模块

有 11 个模块需要的部署面，在六个参考画像里都不存在：Agent 原生控制面、两个厂商运行时 API、一条纯硬件路径。它们留在树里，因为确实有客户那样部署；但不计入覆盖率分母，也不会被任何画像默认开启。

加自己的模块

python -m inkblade sdk new my-module
python -m inkblade sdk lint my-module
python -m inkblade sdk validate my-module

SDK 会强制严格 manifest、把入口限制在模块目录内、记录一个需要你显式接受的 SHA-256 指纹，并校验结果 schema。没有自动信任：没录过指纹的插件，就算躺在磁盘上也不会运行。

向上游提交需要三样：manifest、dry-run 路径、测试。只能对着真实集群跑的模块也欢迎，但要附一份可回放的 fixture，否则 CI 没法验证。
