## 5. Contract

- Every module is a declarative template (`template.json`), executed natively by the Rust probe (`inkblade-probe run-template`/`task`).
- No Python, shell interpreter or module code is dropped into the target Pod.
- `probe-bootstrap` is the only host-executed module and only drops the Rust binary.
- Missing probe / missing target surface fails explicitly; there is no adapter or host fallback.
- Legacy per-family Python tests for `run.py` internals were retired with the execution path; `tests/test_probe_*.py` replace them with two-state template execution and evidence digests.

## 6. What the native sweep does and does not prove

- Proves: every template lowers to the Rust template engine, runs in a real Linux guest through the framed SSH protocol, returns a non-error result in the `vulnerable` state, and repeats identically (canonical digest) over 3 runs per state.
- Does not prove: a true negative control for every template. Templates whose inputs come from a fixture file (not from the mock target) receive the same input in both states, so the `fixed` run can still report the same finding. **237/286** templates report the same finding in both states and are execution-verified only; **49/286** report no identical finding, and **35/286** return `status=ok` in the fixed state — only that last group meets the strict `verified` definition in `DYNAMIC-VERIFICATION.md` §8.
- The target is a local mock range (`lab/template_range.py`), not a production cluster; findings demonstrate detection logic, not live exposure.
