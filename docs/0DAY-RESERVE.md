## 12. 方法与限制

- 动态复核：新增发现使用 `lab/zeroday_reserve/` 真实上游源码/路由 + 证据哈希；历史条目复用 `projects/repro-2026-10/`、`projects/agent-2026-10/` 与 `lab/upstream_verify/` 的已落盘动态证据，并在 registry 中标注 `mode=evidence-reused`；能重跑的条目另有 `mode=rerun`。
- 查新：`tools/novelty-check.py` 查询 OSV、NVD、GitHub Advisory、GitHub commit/code 搜索与厂商 security/advisory 页面；每次请求原始结果缓存于 `corpus/novelty/cache/`。
- 查新补强（2026-10-27）：GitHub 搜索对仓库改名返回 422，工具先解析 canonical repo 再重试；无版本/commit 钉的条目改查 OSV 包级（全版本）并在 PyPI 身份不符/占位包时记录 *受控 N/A*；commit 只在含 CVE/GHSA ID 或 subject 同时出现修复动词与 sink 关键词时计为公开，避免把 rename/lint/docker `--privileged` 误判为披露。
- 离线/限流：缓存缺失、401/403、超时、无包映射均标 `inconclusive`，**不默认未公开**。GitHub 未认证 code search 返回 401，工具降级到 grep.app + 本地上游树扫描并在结果中记录 `via`。
- 不自动外发：披露状态仅在本 registry 与 `docs/0DAY-DISCLOSURE.md` 中记录。
