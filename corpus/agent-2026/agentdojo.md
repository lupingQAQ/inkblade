# AgentDojo — 工具返回不可信前提下的注入评测

- 分类：agent-2026 / 评测与提示注入
- 来源：ETH Zurich SRI / Invariant Labs（arXiv 2406.13352，NeurIPS 2024 D&B）
- 核验日期：2026-10-25；核验状态：verified（webfetch 200，摘要页命中）

## 来源
- https://arxiv.org/abs/2406.13352
- https://github.com/ethz-spylab/agentdojo

## 核验（实际读到的）
- 问题：agent 把文本推理与外部工具调用结合，但**工具返回的数据可劫持 agent** 去执行恶意任务（间接提示注入）。
- 设计：不是静态测试集，而是可扩展环境；**97 个真实任务**（邮件、网银、旅行预订等）、**629 个安全测试用例**，含多种攻击与防御范式。
- 结论：攻击与防御都仍有挑战；SOTA LLM 在**没有攻击**时也会失败不少任务；现有注入攻击能破坏部分安全属性但非全部。
- 明确目标：推动「可靠且鲁棒」的 agent 设计原则。

## 架构要素
- 威胁模型：数据/工具输出不可信，agent 的「读」与「写」能力组合产生注入面。
- 评测维度：任务效用（utility）× 安全属性（security），两者要同时看。
- 可扩展：新任务/新攻击/新防御都能加。

## 对我们的启示
- 这个威胁对我们是**新面**：`explorer` 的 LLM 只读候选集（`explorer.py:70-94`），但若接入网页/资产指纹/工具返回，就会遇到间接注入（G09 缺评测，G08 缺隔离）。
- 我们的三层证据与审批能降低「注入→执行」的成功率，但不能替代输入隔离；需要在工具层做「数据/指令分离」与来源标注。
- 合规上对应 ASI01/ASI02/ASI06；AgentDojo 的 security cases 可作为我们 MCP 工具面的回归套件。
