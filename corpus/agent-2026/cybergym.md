## 核验（实际读到的）
- 规模：**1,507 个真实漏洞、188 个软件项目**；可调难度/分析设置。
- 主任务：只给漏洞文字描述 + 对应代码库，让 agent **生成能复现漏洞的 PoC 测试**。
- 结果：最强组合也只有 **~20% 成功率**，说明任务整体很难；基准能区分 agent/模型能力。
- 额外产出：发现 **34 个零日漏洞**、**18 个历史上不完整的补丁**——评测本身产生真实安全影响。
- 版本：v1 2025-06-03，v2 2025-10-08，v3 2026-03-24。

## 架构要素
- 评测=「可执行结果」而非选择题：PoC 必须真的触发漏洞。
- 动态难度 + 真实代码库，避免刷榜。
- 评测与漏洞挖掘同构：能评分就能发现。

## 对我们的启示
- 我们没有任何 agent 级评测（G09）：只有模块单测/链 e2e，无法回答「换模型/加记忆/加技能后是否更强」。
- CyberGym 的口径可直接借用：以「PoC 是否复现」为金标准，而不是「模型说成功了」。我们的 `verify-effects.py` 已是同类思想（真效果验证），可以把它升级成评分器。
- 评测必须绑定授权与隔离：真实漏洞 PoC 只能在沙箱/授权靶场跑（G08 是前置）。
