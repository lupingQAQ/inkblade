平台能力

  • 一条执行路径。 立足、Rust 探针、帧通道、Pod 内任务、子探针、证据。
  • 目标侧零解释器。 静态二进制在 distroless、scratch 与 Python 镜像上跑同一套模板。
  • 探针树。 probe_id 与 parent_id、独立子 token、更严格的继承、有界的深度与扇出、先子后父清理。
  • Agent 运行时。 带预算的目标图，含决策轨迹、journal 恢复与零执行回放。
  • 跨集群中继。 集群间用同一套帧协议，并留下覆盖证明。
  • 证据在边界产生。 任务结果、步骤日志、产物、SHA-256 manifest、流量表与清理回执。
  • 规则可重放。 准入、运行时、网络三类规则包，输出拦截 / 检出 / 漏过矩阵。
  • 报告与控制台。 双语渗透与修复报告、SARIF / OCSF / VEX 导出、本地控制台。
02

一条执行路径

三个平面，一棵探针树

控制端不在目标侧执行任何逻辑。它负责授权、渲染模板、执行预算和归档证据。探针是 Pod 内唯一运行的代码。

执行路径
立足 ──▶ Rust 探针 ──▶ 帧通道 ──▶ Pod 内任务
                                   │
                                   ├─▶ 子探针 ──▶ 子探针
                                   └─▶ 证据 ──▶ 报告 / 规则 / 控制台

三个平面

  • 模板面。 template.json 声明输入、载荷、步骤、computed 状态、检查项、发现与产物。
  • 探针面。 静态 Rust 二进制使用 HMAC 认证的帧协议，执行 http、tcp、exec、fs、k8s、socks 与 spawn。
  • 控制面。 Python 执行授权、范围、级别、备份与审计校验，并把探针证据折成发现。

探针树

每颗探针都有 probe_id 与 parent_id。子探针继承父探针的只读状态、命令白名单与预算，且只能更严格。清理先子后父，避免留下仍持有 token 的孤儿。

03

静态 Rust 探针

一个二进制、286 个模板、目标侧无解释器

探针是 linux/amd64 与 linux/arm64 各一个静态 musl 二进制。模板是 JSON 数据；目标 Pod 不需要 Python、shell、curl 或其他解释器。

探针操作

操作做什么
collect采集主机、Pod、进程、网络与 Kubernetes 上下文。
exec在预算内执行白名单命令。
audit-exec执行命令并留下审计轨迹与时序记录。
read-file读取文件，带大小上限与 SHA-256 哈希。
list-files列出目录树与元数据。

download分块流式回传文件。
spawn启动子探针，独立 token、更严格预算。
dial向范围内目标建立 TCP 或 UDP 连接。
socks暴露回环 SOCKS5 监听，兼容本地工具。
beacon经帧通道发送心跳与姿态更新。
cleanup移除产物并确认探针树已清空。

每个操作都受预算与范围约束，并写入证据库；探针树先子后父清理。

04

代理协议支持

回连传输与 ML 服务代理

回连通道与 ML 代理是两层：通道在控制端与探针之间承载帧，代理在探针与范围内目标之间承载服务协议。

层支持
回连通道TLS · WSS · HTTPS · QUIC · WebTransport（experimental）· MASQUE
ML 服务代理gRPC · Redis · TCPStore · NCCL · UCX · ZMTP（experimental）
SOCKS5仅回环兼容（127.0.0.1）

认证与加密

  • 每个帧都带 token 与 HMAC；token 或 MAC 不对即断开。
  • TLS、WSS、HTTPS、QUIC 与 WebTransport 用 SHA-256 pin 校验控制端证书，可选 CA 文件。
  • gRPC、Redis、TCPStore、NCCL 与 UCX 代理走 TLS；ZMTP 启用时使用 CURVE 与 Z85 密钥。
  • SOCKS5 只留在回环，是本地工具的兼容路径，不是全网代理。

06

从立足到报告

九个阶段，每步都留下下一步能校验的东西

顺序就是产品。任何阶段都可以拒绝；拒绝就地停下。

  • 1立足session open 记录入口方式、目标、命名空间、Pod 与凭据指纹。
    → 会话记录
  • 2Rust 探针probe deploy 投放静态二进制并登记身份与哈希。
    → 探针身份
  • 3通道channel listen 接收探针主动回连；存在本地命令通道时也可用 stdio 通道。
    → 通道状态
  • 4检测session run、run 与 agent run 按十层执行模板。
    → 发现、证据
  • 5逃逸execute 解析链；写步骤先过备份校验。
    → 逃逸路径
  • 6横向通道转发、子探针与 agent 图边测绘内部可达性。
    → 可达图
  • 7多探针probe spawn 扩展探针树；子探针继承更严格的预算与白名单。
    → 探针树
  • 8跨集群agent relay 连接集群；agent coverage 写出闭合证明。
    → 中继状态、覆盖证明
  • 9报告 / 规则 / 控制台report、export、rules generate 与 ui 收束项目。
    → 报告、规则包、控制台

写权限校验结果

校验拒绝条件信号
授权没记录、窗口过期、资产越界。exit 91

07

探针优先接入

安装、接入、投放、运行、报告

从控制台开始，接入你已有的探针或立足点。默认立足点是普通、最低权限的 Pod：非 root、无 hostPath/privileged、无 kubeconfig，只有出站 TCP。

  1. python -m pip install -e .安装控制端。Python 3.10 – 3.13，不需要编译器。
  2. python -m inkblade up启动控制台、浏览器登录、签授权记录。
  3. python -m inkblade probe list接入已有探针；控制端监听，探针主动回连。
  4. python -m inkblade session open --mode foothold ...用已有 shell、SA token 或 RCE 完成首次投放。
  5. python -m inkblade agent run --probe <probe-id> ...通过探针通道执行检测，再出报告。
终端 · 探针优先
$ python -m inkblade up
$ python -m inkblade quickstart
$ python -m inkblade probe list
$ python -m inkblade channel listen
$ python -m inkblade session open --mode foothold --target <target>     --credential-source pod-shell --namespace <namespace> --pod <pod>
$ python -m inkblade probe deploy --session <session-id> --via rce     --binary ./inkblade-probe-linux-amd64 --probe-token-file ./probe.token --allow-write
$ inkblade-probe reverse --host <controller> --port <port>
$ python -m inkblade agent run --probe <probe-id> --objective read-only-recon --workspace ./work
$ python -m inkblade report --run <run-id> --lang bi

子探针由父探针用 probe upload + probe spawn 投放，并以同样方式回连。存在本地命令通道时可用 stdio 通道（channel start）。kubeconfig 是可选的，只用于首次批量 bootstrap。文档站点在本地：python -m inkblade docs 在 127.0.0.1:8766 服务 docs/ 并打开浏览器；--no-browser 不打开浏览器。

Wheel、容器、Helm

一个控制端，三种交付方式

控制端是一个无第三方依赖的 Python 包；探针是独立的静态二进制。

wheel
python -m pip wheel . --no-deps -w dist/
python -m pip install --no-index --find-links dist/ inkblade
容器
docker build -t inkblade:0.2.0 .
docker run --rm -v inkblade-data:/data inkblade:0.2.0 up
helm · 默认只读
helm install inkblade deploy/helm/inkblade   --namespace inkblade --create-namespace

uid 10001、根只读、证据落在 PVC。默认只给读动词；写操作要 readOnly=false、rbac.allowWrite=true 与签署记录。卸载保留 PVC。

10

安全与授权

授权是使用前提，不是功能开关

没有签署记录，InkBlade 拒绝运行。每个阶段都有自己的校验。

  1. RoE 记录目标、范围、级别、时间窗与应急联系人；哈希钉存，跟着每次 run 走。
  2. 默认只读采集、探测、读文件与只读模板不需要额外开关。
  3. 五重写权限校验会话级别、--allow-write、meta.writes、backup-write 模式、备份回执。
  4. 备份与回滚写前快照，两者都记录，逐步恢复。
  5. 审计与证据每次探针动作与文件访问进入证据库，带 SHA-256 manifest。
  6. 急停inkblade abort 停工作区；agent stop 停单个 run。
控制保证什么
授权哈希一次 run 的授权是一个文件，不是一场会。
范围与级别越界或超级别的动作在执行前拒绝。
备份回执没有可恢复快照就没有写操作。
证据 manifest每条发现都能落到 task、step、artifact、probe 或 manifest 哈希。

仅限授权使用。没有书面授权就不做。对不归你所有的系统动手，在多数司法辖区属于违法。没有签署记录，软件会拒绝。

安全问题走 SECURITY.md 的私密渠道；公开 issue 不要贴利用细节。

11

常见问题

接入、探针、检测、授权、交付

目标 Pod 要装 Python 吗？

不要。探针是静态 Rust 二进制，模板是 JSON。目标只需要 Linux 内核、可写临时目录或 memfd_create，探针进程继承 Pod 的命名空间与 ServiceAccount。

探针怎么进 Pod？

kubectl、ServiceAccount token、共享卷、EphemeralContainer 清单或授权 RCE 回调。每种方式都有前置条件，也会留下痕迹。

探针是不是后门？

不是。它不持久化、不改启动项、不改镜像、不回连固定 C2。它只在授权会话内运行，执行已注册模板，默认只读，写操作过校验，退出时清理。

写操作怎么保证安全？

五重校验：授权覆盖目标/级别/时间窗、--allow-write、meta.writes 与写步骤、backup-write 模式、备份回执。写后回读哈希，失败回滚。

能离线吗？

能。控制端不需要外网，探针不需要包索引，模板与规则包随发布物带入。

能商用或 fork 吗？

Apache-2.0 允许商用与 fork。保留 LICENSE 与 NOTICE，不要用 InkBlade 商标命名 fork。
